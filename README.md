# Телеграм-планировщик для дочери

Telegram-бот + веб-панель для родителя. Родитель управляет расписанием уроков
и домашними заданиями через простую веб-панель (браузер), а бот сам
присылает дочери напоминания в Telegram.

## Возможности

- **Расписание уроков** — недельная сетка (день недели, время, предмет, кабинет, учитель).
- **Домашние задания** — список с дедлайнами и отметкой «выполнено».
- **Автоматические напоминания** дочери в Telegram:
  - утренняя сводка (расписание + ДЗ на сегодня) в заданное время;
  - напоминание за N минут до каждого урока;
  - напоминание в день сдачи ДЗ и заранее (за N дней до дедлайна).
- **Команды в боте** для дочери: `/today`, `/week`, `/homework`, `/help`.
- Веб-панель защищена логином/паролем — доступна только вам.
- Привязка бота к аккаунту дочери — по одноразовому коду, который вы
  генерируете в веб-панели (случайные люди подключиться не смогут).

## Как это устроено

Один Python-процесс запускает сразу три вещи:
1. Telegram-бот (polling, `aiogram`).
2. Веб-панель (`FastAPI`, на порту 8000 по умолчанию).
3. Планировщик, который раз в минуту проверяет, не пора ли отправить
   напоминание (`APScheduler`).

Данные хранятся в SQLite-файле `data/bot.db` — отдельная база данных не нужна.

## Быстрый старт (локально, для проверки)

1. Создайте бота через [@BotFather](https://t.me/BotFather) командой
   `/newbot` и получите токен вида `123456789:AA...`.
2. Установите Python 3.11+ и зависимости:
   ```bash
   python -m venv .venv
   source .venv/bin/activate  # Windows: .venv\Scripts\activate
   pip install -r requirements.txt
   ```
3. Скопируйте `.env.example` в `.env` и заполните:
   ```bash
   cp .env.example .env
   ```
   - `BOT_TOKEN` — токен от BotFather.
   - `ADMIN_USERNAME` / `ADMIN_PASSWORD` — логин и пароль для входа в веб-панель.
   - `SESSION_SECRET_KEY` — любая длинная случайная строка.
   - `TIMEZONE` — например, `Europe/Moscow` (можно поменять позже в настройках).
4. Запустите:
   ```bash
   python run.py
   ```
5. Откройте `http://localhost:8000` в браузере, войдите под `ADMIN_USERNAME`/`ADMIN_PASSWORD`.
6. В разделе **Настройки** нажмите «Сгенерировать код привязки» и передайте
   код дочери — она открывает бота в Telegram и отправляет `/start КОД`.
7. Заполните расписание и домашние задания — напоминания начнут приходить
   автоматически.

## Где сейчас развёрнуто

Бот работает на VPS (Hetzner Cloud, тариф CX23, Хельсинки), в Docker
(`docker compose`, `restart: unless-stopped`) — то есть **работает сам по
себе, постоянно, независимо от того, включён ли ваш компьютер и открыты ли
какие-либо SSH-сессии**. Закрыть окно PowerShell или выключить свой ноутбук —
безопасно, бот и напоминания продолжат работать на сервере.

Веб-панель **не открыта в интернет напрямую** (это осознанное решение ради
безопасности) — доступ к ней только через SSH-туннель со своего компьютера
(см. раздел «Управление сервером» ниже).

## Управление сервером

### Данные для входа
- **IP сервера:** `37.27.181.64`
- **Пользователь:** `root`
- **Вход:** по SSH-ключу (пароль отключён/не нужен) —
  ```powershell
  ssh root@37.27.181.64
  ```
- Код бота лежит в `/root/bot` на сервере.

### Повседневные команды на сервере (после `ssh root@37.27.181.64`)

Посмотреть, что происходит (логи бота в реальном времени):
```bash
cd /root/bot
docker compose logs -f
```
(`Ctrl+C` — выйти из просмотра логов, сам бот при этом не останавливается)

Проверить, что контейнер запущен:
```bash
docker compose ps
```

Перезапустить бота (например, после правки `.env`):
```bash
docker compose restart
```

Обновить код бота до последней версии и пересобрать:
```bash
cd /root/bot
git pull
docker compose up -d --build
```

Остановить бота полностью (например, для обслуживания):
```bash
docker compose down
```
Запустить обратно:
```bash
docker compose up -d
```

### Как открыть веб-панель со своего компьютера

Панель специально не торчит в открытый интернет — нужен туннель.

1. Откройте **отдельное** окно PowerShell (SSH-сессию на сервере при этом
   можно держать открытой в другом окне или закрыть — не важно).
2. Выполните:
   ```powershell
   ssh -L 8000:localhost:8000 -N root@37.27.181.64
   ```
   Окно «зависнет» без вывода — это нормально, значит туннель работает.
   **Не закрывайте это окно**, пока пользуетесь панелью.
3. Откройте в браузере: `http://localhost:8000`
4. Закончили — закройте окно с туннелем (`Ctrl+C`), доступ снова закроется.

Когда именно открывать туннель — только когда нужно зайти в панель
(поменять расписание, добавить ДЗ, сгенерировать код привязки). В остальное
время бот и так работает сам, туннель для этого не нужен.

### Доступ с телефона

Открыть `http://localhost:8000` с телефона **напрямую нельзя** — SSH-туннель
из инструкции выше работает только на том компьютере, где вы его запустили;
адрес `localhost` на телефоне означает сам телефон, а не сервер.

Варианты для доступа с телефона:
- **SSH-клиент с проброса портом** (например, приложение Termius) — можно
  настроить такой же туннель `-L 8000:localhost:8000`, как в PowerShell, и
  дальше открывать `http://localhost:8000` уже в браузере телефона.
- **Tailscale** — начинали настраивать, уперлись в сбой при авторизации
  через GitHub. Если хотите — можно вернуться и доделать: тогда на телефоне
  просто открывается приложение Tailscale и адрес сервера в его приватной
  сети, без туннелей и паролей каждый раз. Скажите, если хотите продолжить.

На практике веб-панель нужна нечасто (в основном раз в неделю — обновить
расписание/ДЗ), так что для этого разумно пользоваться компьютером через
SSH-туннель, а телефон — только для самого Telegram-бота (им как раз
пользуется дочь, и он не требует никакого туннеля).

## Структура проекта

```
app/
  bot/bot.py        — обработчики команд Telegram-бота
  web/server.py      — веб-панель (FastAPI) и HTML-шаблоны
  web/templates/      — страницы веб-панели
  models.py           — таблицы БД (Student, Lesson, Homework, PlannerSettings, ReminderLog)
  reminders.py         — логика проверки и отправки напоминаний (запускается раз в минуту)
  services.py, formatting.py, constants.py — общие утилиты
run.py                 — точка входа: запускает бота, веб-панель и планировщик вместе
```

## Безопасность

- Веб-панель закрыта логином/паролем из `.env` — обязательно поменяйте
  значения по умолчанию.
- `.env` и файл базы данных (`data/`) не должны попадать в git — они уже
  добавлены в `.gitignore`.
- К боту в Telegram может подключиться только тот, кто знает код привязки,
  который видите и генерируете только вы в веб-панели.

## Автоматический бэкап базы данных

Скрипт `scripts/backup_db.sh` делает безопасную «горячую» копию
`data/bot.db` (через `sqlite3 .backup`, поэтому не повреждает файл, даже
если бот в этот момент пишет в базу), сжимает её и хранит последние
14 дней (настраивается через `KEEP_DAYS`), удаляя более старые копии.

Настройка автозапуска на сервере (systemd-таймер, запуск раз в сутки в 03:30):

```bash
# sqlite3 CLI нужен на хосте (не в контейнере) — скрипт запускается снаружи
apt install -y sqlite3

# если склонировали репозиторий не в /root/bot — поправьте путь
# в scripts/systemd/bot-backup.service (ExecStart)
cp scripts/systemd/bot-backup.service /etc/systemd/system/
cp scripts/systemd/bot-backup.timer /etc/systemd/system/

systemctl daemon-reload
systemctl enable --now bot-backup.timer
```

Проверить, что всё настроено и когда следующий запуск:
```bash
systemctl list-timers bot-backup.timer
```

Запустить бэкап вручную (не дожидаясь 03:30) и посмотреть лог:
```bash
systemctl start bot-backup.service
journalctl -u bot-backup.service -n 20
```

Бэкапы лежат в `backups/` рядом с проектом. Это защищает от повреждения
базы или случайного удаления, но не от полного отказа диска/сервера —
для этого нужна копия вне сервера (ниже) и хотя бы раз проверенное
восстановление (ещё ниже).

### Копия бэкапов вне сервера (на свой компьютер)

Скрипт `scripts/windows/pull_backups.ps1` раз в неделю забирает свежие
`backups/*.gz` с сервера на ваш Windows-компьютер, используя тот же
SSH-ключ, что и обычный вход на сервер — отдельно ничего настраивать
не нужно.

1. Скачайте скрипт на компьютер (например, в `C:\Scripts\`):
   ```powershell
   New-Item -ItemType Directory -Force -Path C:\Scripts | Out-Null
   Invoke-WebRequest -Uri "https://raw.githubusercontent.com/TatianaOv/rep/claude/telegram-scheduler-bot-cd9lb7/scripts/windows/pull_backups.ps1" -OutFile "C:\Scripts\pull_backups.ps1"
   ```
2. Проверьте вручную, что работает:
   ```powershell
   powershell.exe -ExecutionPolicy Bypass -File C:\Scripts\pull_backups.ps1
   ```
   Бэкапы должны появиться в `C:\Users\<вы>\KirasDayBackups`.
3. Поставьте на еженедельный автозапуск через Планировщик заданий Windows
   (например, по воскресеньям в 09:00):
   ```powershell
   schtasks /create /tn "KirasDayBackupPull" /sc weekly /d SUN /st 09:00 /tr "powershell.exe -ExecutionPolicy Bypass -File C:\Scripts\pull_backups.ps1"
   ```
   Задание выполнится, только если компьютер в этот момент включён и
   в сети — если он иногда выключен, копия просто будет чуть более
   свежей/старой неделю от недели, это не страшно.

### Проверка восстановления (сделать хотя бы один раз)

Непроверенный бэкап — это гипотеза, а не гарантия. Скрипт
`scripts/restore_test.sh` поднимает **отдельный, временный** контейнер
с копией последнего бэкапа на отдельном порту — реальный бот и его
база при этом не трогаются.

На сервере:
```bash
cd ~/bot
./scripts/restore_test.sh
```
Дальше откройте туннель с компьютера на порт, который скрипт напечатает
(по умолчанию 8001):
```powershell
ssh -L 8001:localhost:8001 root@37.27.181.64
```
и зайдите на `http://localhost:8001` под тем же логином/паролем, что и
в обычную панель — проверьте, что расписание и домашние задания на
месте. Закончили — остановите тестовый контейнер:
```bash
docker stop restore-test
rm -rf ~/bot/restore_test
```
